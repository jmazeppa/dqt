# DQTステータス計算の知見

## 対象と前提

本書は `status.html`、`status.json`、`self_calc.html` および [Issue #16](https://github.com/jmazeppa/dqt/issues/16) の実測値から確認した計算仕様をまとめる。現在の `status.json` はランク9・Lv Max相当であり、データは約8か月前のもの。ゲーム内仕様との完全一致は保証しない。

ステータス配列の順序は常に次の6要素である。

```text
[HP, MP, 攻撃(ATK), 守備(DEF), 素早(AGL), 賢さ(WIS)]
```

## `status.json` と0凸基礎値

- `base_status_at_max_level`: 覚醒倍率などを適用する前のLv Max基礎値
- `panel_status_at_max_level`: 才能開花・スキルパネル等の固定加算
- `awakening_table[].additives`: 覚醒段階ごとの固定加算
- `awakening_table[].magnifiers`: 覚醒倍率。通常は0凸0%、1～5凸で5～25%
- `characteristic_additives`: 存在する場合はパネル値より優先する特性加算

完凸図鑑値から基礎値を作る従来手順は、おおむね次の考え方である。

```text
ceil(完凸図鑑値 ÷ 1.25) − 覚醒固定値 − パネル・特性固定値
```

キャラクター固有の覚醒固定値が不明な新キャラでは、無凸値へ25%を加えるだけの結果は概算となる。

## `status.html` の計算式

加算部 `A` と倍率部 `M` を次のように扱う。

```text
A = 基礎値 + 覚醒固定値 + 装備固定値 + 有効なパネル・特性固定値
M = 1 + MR補正率 + 覚醒倍率
編成画面値 = floor(A × M)
```

装備、開花、パネルの固定値にもMR補正と覚醒倍率が掛かる。端数は最終計算時に切り捨てる。

MRは `HP → 守備 → 素早 → 攻撃 → 賢さ → MP` の順で、1レベルごとに対象ステータスが1%上昇し、6レベルで一巡する。MR0は補正なし。例えばMR60では全ステータスが+10%となる。

## 戦闘中upとHP補正

HPは闘技場補正として `floor(A × M × 1.30)`。MPは変化なしとして表では `-` を表示する。その他は、戦闘中バフ率を既存倍率へ加算する。

| ステータス | 1up | 2up | 3up |
|---|---:|---:|---:|
| 攻撃・賢さ | +15% | +30% | +45% |
| 守備 | +25% | +50% | +75% |
| 素早 | +20% | +40% | +60% |

```text
戦闘中値 = floor(A × (M + バフ率))
```

重要なのは、バフ率が表示済みステータス全体への単純乗算ではなく、内部の加算部 `A` に対して倍率部へ加算される点である。

## `self_calc.html` の3モード

### A. 新キャラ無凸用

入力値を0凸基礎値とみなし、0～5凸を選択して1凸あたり5%（最大25%）の覚醒倍率を適用する。初期値は5凸。キャラクター固有の覚醒固定値は含めない。Issue #16のデスピサロを5凸で検証すると、攻撃 `547 → 683`、素早 `489 → 611`、賢さ `241 → 301` が一致した。HPと守備は未知の固有固定値があるため一致しない。

### B. 理論値計算用

完凸図鑑値を入力し、`ceil(入力値 ÷ 1.25)` で覚醒前相当の整数値へ戻す。最終結果の端数切り捨てとは異なり、逆算時は切り上げが必要である。アマテアの素早さは `ceil(557 ÷ 1.25) = 446` となり、固定値182・MR11%を含めると `floor((446 + 182) × 1.36) = 854` となる。

Issue #16のデスピサロでも、攻撃 `683 → 547`、素早 `611 → 489`、賢さ `301 → 241` を逆算でき、25%を再適用すると元の完凸図鑑値へ戻る。HP・守備のように覚醒固定値が含まれるステータスは、倍率だけでは0凸基礎値へ戻せない。例えば守備609は整数基礎値への25%だけでは生成できないため、固有固定値が不明な場合は概算として扱う。

[タクトリサーチの開幕すばやさランキング](https://tact-research.net/character/openspeed/) と各キャラクターページの完凸値を照合した結果も次のとおり一致した。装備182・MR11%では倍率部が `1 + 25% + 11% = 1.36` となる。

| キャラクター | 完凸図鑑値 | 逆算基礎 | 装備 | MR | 開幕値 |
|---|---:|---:|---:|---:|---:|
| アマテア | 557 | 446 | 182 | 11% | 854 |
| 魔剣士ピサロ | 645 | 516 | 182 | 11% | 949 |
| ゲルダ | 637 | 510 | 182 | 11% | 941 |
| サンタアリーナ | 636 | 509 | 182 | 11% | 939 |

#### 開幕ランキングを使った回帰テストの作成手順

1. 開幕すばやさランキングをレアリティ・タイプ等で絞り、キャラクター名、基礎、装備、MR、開幕値を控える。
2. 同サイトのキャラクター名を開き、「最大ステータス（マスターランクを除く育成時）」のすばやさを完凸図鑑値として控える。
3. 戦闘開始時バフ、編成バフ、ビーストチャージ、覚醒プラスなど、Bモードが扱わない補正が表示された行はテスト対象から除外する。
4. `ceil(完凸図鑑値 ÷ 1.25)` がランキングの基礎と一致することを確認し、`floor((逆算基礎 + 装備) × (1 + 0.25 + MR))` が開幕値と一致することを確認する。
5. `tests/test_self_calc_playwright.py` の `theory_cases` に、キャラクター名、完凸図鑑値、期待する開幕値を固定値として追加する。外部サイトをテスト実行時に取得せず、掲載値が更新された場合は出典と計算過程を再確認してテストデータを更新する。

テストでは装備182を素早の固定値へ設定する。素早のMR11%を再現するためMRレベル63を選ぶ（MRの加算順により、MR63時点で素早は11%）。その後Bモードの基礎列と期待する開幕値を比較する。

### C. 戦闘中計算用

入力値にはMR、装備、開花、パネル等が既に含まれるため、それらのフォームを隠す。覚醒数は0～5凸から選択し、初期値は5凸。攻撃・守備・素早・賢さは、入力値がbase／1up／2up／3upのどれかを指定できる。

相手のMRが不明な場合を想定し、結果表はMR9%、10%、11%、12%の4列を表示する。各MR候補について、入力値と選択中の覚醒・up段階を満たす整数の内部加算部 `A` を探す。

```text
入力値 = floor(A × (1 + 覚醒倍率 + 仮定MR + 入力段階率))
結果 = floor(A × (1 + 覚醒倍率 + 仮定MR + 対象段階率 + 状態補正率))
```

一致する整数 `A` がないMR候補だけは、入力値を入力時倍率で割った概算値を使い、画面に `≈` を付ける。10% down／base／10% up／20% upの状態補正はHP・MPには適用しない。

完凸ゾーマの素早さがbase 781、1upかつ10% downで839となる例は、覚醒25%・MR10%・`A=579`で一致する。

```text
floor(579 × 1.35) = 781
floor(579 × (1.35 + 0.20 - 0.10)) = 839
```

## Issue #16による実測検証

v0.1.0までの単純割戻しが厳密値にならないことを次の例で確認した。この知見をもとに、v0.2.0では覚醒倍率とMR候補を分離した逆算方式へ変更した。

| 対象 | 遷移 | ツール概算 | 実測 |
|---|---|---:|---:|
| デスピサロ 攻撃 | base→1up | 1013 | 979 |
| デスピサロ 守備 | base→2up | 1047 | 948 |
| デスピサロ 素早 | 1up→2up | 904 | 875 |
| デスピサロ 賢さ | base→1up | 373 | 361 |
| エスターク 攻撃 | 1up→2up | 989 | 966 |
| エスターク 守備 | base→1up | 830 | 787 |
| エスターク 素早 | base→1up | 885 | 852 |

実測値に厳密一致させるには、表示値だけでなく内部の `A`、またはそれを復元できる基礎・固定値・各倍率が必要である。未知の場合は正確値と表示せず、概算であることを明示する。

## 未実装・要検証のステータス補正

理論計算とゲーム内表示が一致しない原因として、次の2機能が未考慮である。いずれも現時点では未入手・未検証のため、適用対象、加算順序、丸め位置を確定仕様として扱わない。

### 覚醒プラス（6～35凸）

- 通常の5凸より先の育成要素。
- 6種類のステータスから1つを選び、各ステータスを最大`+5`まで強化できると考えられる。
- 6ステータス×5段階に通常の5凸を合わせ、表記上の上限が35凸となる。
- 各`+1`は、対象ステータスの無凸状態の値へ1～5を固定加算する可能性がある。
- `status.json`、`status.html`、`self_calc.html` には未実装。

「無凸値への固定加算」か、「覚醒・MRなどの倍率適用前後のどこで加算するか」は未確認である。実装時は、覚醒プラスなし／ありの同一キャラクター実測値を比較して確定する。

### 極み覚醒マスターバッジ

- 全キャラクターへ一律に適用されるステータス補正と考えられる。
- 例として「攻撃力+1%」があり、賢さ・守備などステータス別のバリエーションが存在する。
- 対象ステータスの無凸状態を基準に1%加算する可能性がある。
- `status.json`、`status.html`、`self_calc.html` には未実装。

この1%を既存の倍率部 `M` へ加えるのか、無凸値から求めた固定値として加算部 `A` へ入れるのかは未確認である。全キャラクター一律補正であるため、同じバッジ条件の有無を比較できる実測値が必要となる。

### 理論値への影響

上記補正が有効なゲーム内表示と、未対応のツール結果を比較すると差が生じる。原因不明の差を直ちに既存の覚醒、MR、装備、パネル、丸め処理の不具合と判断せず、覚醒プラスと極み覚醒マスターバッジの適用有無を確認する。

## 実装・検証上の注意

- 浮動小数点の中間値を不用意に丸めず、仕様で定めた最終地点で `floor` を適用する。JavaScriptの誤差で整数が1小さくならないよう、切り捨て直前に微小値を加える。
- 図鑑値、編成画面値、戦闘中表示値を混同しない。
- 属性ランク、MR、装備、覚醒固定値、パネル値が同時に含まれる実測値は、効果を分離できない場合がある。
- 覚醒プラスと極み覚醒マスターバッジの有無も検算条件に含める。
- 新しい式は既知の入力段階を強調し、推定結果には `≈` を付ける。
- Issue等の検算データには、凸数、覚醒プラス、極み覚醒マスターバッジ、ランク、MR、装備、パネル、戦闘中段階を併記する。
